# woofWoofCPU — guide for Claude Code sessions

A personal macOS menu bar app: an animated dog that watches per-app CPU and memory, escalates napping → sniffing → growling → barking when something stays over its limit, and lets the user Quit (⌥ Kill), Snooze or Ignore it. `miawMiawCPU` is a companion CLI that loads the Mac on purpose to test the dog.

## Build, test, run — always through the Makefile

`xcode-select` on this Mac points at the Command Line Tools, whose Swift Testing macro plugin fails on multi-file test targets. The Makefile exports `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, so never call `swift`/`xcodebuild` directly.

    make test                 # WoofCore + MiawCore tests (FILTER=<Suite> to narrow)
    make build                # XcodeGen + xcodebuild, Debug, warnings are errors
    make run                  # build and launch the Debug app
    make install              # Release build copied to /Applications (the user's live copy)
    make miaw                 # builds bin/miawMiawCPU
    make dist                 # Apple silicon Release app + dmg in dist/, then `make tidy`
    make tidy                 # drop build intermediates, keep dist/ and bin/
    make clean                # tidy + remove dist/ and bin/

After `make install`, relaunch: `pkill -x woofWoofCPU; open /Applications/woofWoofCPU.app`. Never `cd` in shell commands; use paths from the repo root.

## Layout

- `Packages/WoofCore/` — all logic, no AppKit/SwiftUI: libproc sampling (`Sampling/`), grouping helpers under their app (`Grouping/`), limits and breach tracking (`Rules/`), mood state machine (`Mood/`), settings persistence (`Settings/`), quit/kill (`Actions/`), per-tick pipeline and history (`Pipeline/`). Unit-tested with fakes.
- `WoofWoofCPU/` — the app (AppKit + SwiftUI): `App/` (coordinator loop, bark player, launch at login, app icon), `MenuBar/` (status item, animator), `Popover/` (non-activating panel and rows), `Settings/`, `Skins/` (Classic and Pixel pup shown; 8-bit classic and Shiba hidden), `Resources/` (Info.plist generated by XcodeGen, AppIcon, bark sounds).
- `Tools/miawMiawCPU/` — separate Swift package: `MiawCore` (tested logic) + the `miawMiawCPU` executable.
- `scripts/` — `hog.sh` (quick CPU/memory hog), `make-icon.swift` (regenerates the AppIcon PNGs).
- `site/` — Astro landing page for woof.mltru.com.
- `docs/` — design spec (binding), v1 implementation plan, similar-apps research, decisions log, manual checks.

## Conventions

- Swift 6 language mode, strict concurrency, zero warnings. macOS 14 deployment target. No third-party runtime dependencies.
- TDD for WoofCore and MiawCore changes (failing test first). The app target has no test target; verify UI work by building and, when visual, by rendering images or `screencapture -x` (works on this Mac; the display is 1×, 2560×1440).
- Code comments: short, only what the code can't say. No history narration.
- Commit messages: one line, no body, no trailers, no mention of Claude/Anthropic/model names.
- Git identity for this repo is local: `micmnm@gmail.com`; GitHub auth for this repo goes through `gh` (account micmnm). Don't change it. Remote: `https://github.com/micmnm/woofWoofCPU` (private), branch `main`.
- The spec (`docs/superpowers/specs/2026-10-01-woofwoofcpu-design.md`) is the authority; keep it in sync when behaviour changes.

## Gotchas

- Processes of root/other users can't be read without privileges; v1 watches only the current user's processes.
- Grouping uses the private `responsibility_get_pid_responsible_for_pid` (via `dlsym`) only for `.xpc`-only paths; code inside a `.app` groups under its own outermost `.app`.
- Skins draw menu bar frames as template images only when they have no coloured parts; coloured moods use `labelColor` resolved at draw time.
- Don't write the app's defaults with `defaults write` while it's running — quit it first.
